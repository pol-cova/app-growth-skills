# Onboarding archetypes

Use these as starting hypotheses. Choose based on time-to-value, required setup, risk, and access model. Do not copy an archetype without checking product facts.

## Immediate-value utility

The product can produce its core result during the first session, often in seconds.

Likely direction:

```text
acquisition promise -> minimum input -> product action -> result -> relevant offer
```

Test direct entry against any introductory flow. Defer profiles, preferences, and education. A long questionnaire is suspect unless its answers materially change the immediate result.

Examples include scanners, converters, calculators, single-purpose editors, and identification tools.

## Short setup before value

The product needs a small amount of configuration or user input before producing a result.

Likely direction:

```text
promise -> required inputs -> setup -> personalized result -> offer or activation
```

Explain why each input is needed and show its effect promptly. Use defaults where precision is not required. Consider progressive profiling after the first result.

Examples include planning tools, tailored content apps, and utilities that require a source, goal, or integration.

## Delayed-value habit or behavior product

The desired outcome appears through repeated action over time.

Likely direction:

```text
promise -> intent and context -> credible mechanism -> minimum plan -> commitment -> offer -> first leading action
```

The first session should create credible progress, not pretend the final outcome exists. Activation may be scheduling and completing the first meaningful action, not finishing onboarding or starting a trial.

Examples include fitness, meditation, learning, sleep, and behavior-change products.

## Content subscription

Value depends on access to a catalog, editorial product, or regularly refreshed content.

Allow browsing or a representative preview when rights and economics allow. Use stated interests only if they alter recommendations or the starting feed. Paywall timing depends on the acquisition promise, content availability, and free-access policy.

## Creator or editing tool

Users often arrive with a file or task. Let them create, import, record, or edit before teaching the whole interface. Guide the first unfamiliar action in context, then use the actual preview, export quality, or workflow speed as evidence. A premium boundary may belong at export or at a paid capability.

Likely direction:

```text
promise -> create or import -> guided first action -> preview or result
-> export or premium boundary -> offer
```

## Social or network product

Free participants may create content, invitations, liquidity, or community value. Activation can depend on network density. Model that value before applying hard-paywall conversion benchmarks.

Likely direction:

```text
promise -> minimum identity -> discovery -> first interaction
-> contextual premium opportunity
```

## AI or generative product

The first result can be quick, but novelty-driven trial starts may not predict recurring use. Start from a high-intent input and useful output. Account for generation cost when selecting the free boundary. Measure whether users establish a repeat workflow, not only whether they try the feature once.

Likely direction:

```text
promise -> high-intent input -> generation -> edit or result
-> offer or usage boundary -> recurring-workflow activation
```

## High-trust or regulated product

Health, finance, children, identity, and other sensitive contexts may require consent, eligibility, risk explanation, or account security before value.

Do not optimize away a required safeguard. Separate legal or safety necessity from persuasion. Collect the minimum data and state how it affects the experience.

## Existing-user or restored-access path

Returning users should not repeat new-user persuasion. Detect authenticated or entitled state where possible. Provide sign-in and restore routes without making them hunt through the acquisition flow. Resume incomplete setup without losing prior work.

## Choosing among them

If the product spans archetypes, branch by actual user state or job, not by a decorative quiz. For example, a fitness app may give an immediate workout preview while the long-term outcome remains delayed. The preview can establish mechanism credibility, while activation still depends on completing a workout.
