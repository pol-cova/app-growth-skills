# Patterns and antipatterns

Use this reference to evaluate common onboarding devices. No pattern is automatically required.

## Useful when justified

### Representative product demo

Let the user perform the core action or produce a truthful sample result. This works best when time-to-value is short and the demo does not require sensitive setup.

### Progressive profiling

Collect information when it becomes useful instead of front-loading every possible preference. Preserve prior answers and explain their visible effect.

### Contextual education

Place a short instruction near an unfamiliar control at the moment of use. Avoid a detached tour that users must memorize.

### Honest plan preview

For delayed-value products, show the schedule, curriculum, recommendation logic, or first task generated from real inputs. Distinguish a preview from an achieved outcome.

### Relevant proof

Use sourced evidence that matches the claim, audience, and mechanism. Product-specific evidence is stronger than a broad popularity claim. State important limits.

## Usually harmful or unjustified

### Fake personalization

Repeating a name or selected goal while leaving the product unchanged is not meaningful personalization. Require a downstream branch, recommendation, configuration, or saved state.

### Fabricated loading or analysis

An artificial delay and animated checklist imply work that did not occur. Show real progress only when real work has measurable stages. Otherwise return the result.

### Invented or mismatched statistics

Do not manufacture percentages, imply clinical proof without support, or reuse a benchmark from another category or geography as a product claim. Cite the source and explain fit.

### Pain amplification

Do not intensify insecurity, shame, fear, or urgency to force continuation. Describe the problem accurately and preserve a neutral way to decline.

### Questionnaire theater

Long quizzes can create commitment but also delay value and filter users. Every answer must have an explicit use. If the goal is only persuasion, test a more direct and honest message.

### Permission wall

Do not request notifications, tracking, contacts, location, photos, camera, and microphone as a launch sequence. Trigger each request from its dependent action and support denial.

### Premature rating prompt

Onboarding completion, account creation, or purchase does not prove the user has experienced value. Wait for a meaningful product event and a natural pause.

### Misleading progress

Do not use a progress bar whose denominator changes, a false last step, or repeated "one more thing" screens. If the path branches, communicate progress without pretending it is fixed.

### Forced social proof

Testimonials and user counts do not repair an unclear product mechanism. Verify permission, source, recency, and relevance. Never fabricate them.

### Sunk-cost paywall

Do not collect unnecessary answers mainly to make users feel invested before the offer. Setup before a paywall should create real product state or a relevant result.

## Review question

For any persuasive device, ask what the user would believe if they knew exactly how it was produced. If that knowledge would make the device feel deceptive, remove or rewrite it.
